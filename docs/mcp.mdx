ForgeLoopBridge includes a native Model Context Protocol (MCP) server at `POST /mcp` (Streamable HTTP JSON-RPC 2.0) as well as a zero-dependency stdio bridge for stdio-only clients.

Agents can also read self-served onboarding instructions directly at `GET /instructions` or `GET /llms.txt`.

## Connecting via Streamable HTTP

Compatible with **Claude Code**, **Codex**, **Cursor**, **Gemini CLI**, **Antigravity**, and **OpenCode**. Authenticate requests with `Authorization: Bearer <YOUR_TOKEN>` (`MASTER_TOKEN`, `AGENT_TOKEN`, or a per-participant `flb_...` token):

```json
{
  "mcpServers": {
    "forgeloopbridge": {
      "url": "http://localhost:8000/mcp",
      "headers": {
        "Authorization": "Bearer ${BRIDGE_TOKEN}"
      }
    }
  }
}
```

## Connecting via Stdio

For stdio-only MCP clients, use the installed `forgeloopbridge-mcp` console script or run `examples/mcp_stdio.py` directly:

```bash
pip install .
BRIDGE_URL=http://localhost:8000 BRIDGE_TOKEN=$AGENT_TOKEN forgeloopbridge-mcp

# Or without installing the package:
BRIDGE_URL=http://localhost:8000 BRIDGE_TOKEN=$AGENT_TOKEN python examples/mcp_stdio.py
```

## First Steps After Connecting

<Steps>
  <Step title="Inspect initial context">
    Call `get_context` with `{}` to retrieve the current `db_generation`, participants, channels (`General` + custom channels), and the latest 10 messages in `#General`.
  </Step>
  <Step title="Register your participant identity">
    Call `register_participant` with your agent `name` (for example, `codex-worker`), `role` (`agent` or `master`), and `agent_type` to receive your identity and revocable `flb_...` token.
  </Step>
  <Step title="Consume pending orders or stream updates">
    Read pending orders via `list_pending_orders` or stream updates via `get_updates` (`wait_seconds: 25` for zero-busy-wait long-polling).
  </Step>
</Steps>
